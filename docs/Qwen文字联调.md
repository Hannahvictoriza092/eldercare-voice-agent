# Qwen 云端文字联调

## 启动

在项目根目录执行，使用配置好环境变量的同一个 PowerShell 窗口：

    python -m pip install -r requirements.txt
    python qwen_chat.py

需要环境变量 DASHSCOPE_API_KEY、DASHSCOPE_BASE_URL；QWEN_MODEL 默认 qwen-plus。
地址与密钥沿用之前已验证成功的配置，不要把密钥写入文件或提交仓库。
当前采用兼容接口的非流式 Chat Completions，enable_thinking=false。

看到“你：”后输入自然语言，不要再把中文对话直接输在 PowerShell 提示符后。

    每天早上八点提醒我吃一片测试药。
    对。
    今天早上八点的测试药我已经吃过了。
    救命，我需要帮助。
    救助来了吗？
    帮我生成这周的健康报告。
    查一下我的健康档案。

新增、修改、停用提醒，以及结束呼救、生成待发送周报通知前，助手用中文复述并问“对吗”。
直接在下一轮输入“对”“是的”“确认”“好的”即可执行；“算了”“取消”放弃待确认操作。
可以直接改口，例如“不对，改成九点”：助手重新复述九点的草稿，等再次确认才保存。
“对，不过改成九点”不会当作同意八点。模型传入 confirmed=true 也不能代替本人确认。
如果模型只输出确认清单却没有调用工具，程序会拦截该文本，补一次草稿建立请求。
只有参数校验通过、真实待确认草稿建立后，才展示确认问题；此时“好的”直接保存。
补救仍失败则明确告知尚未建立、尚未保存，不把口头清单当作已完成操作。
确认十分钟内有效；清空会话、退出程序、明确呼救会清除待确认操作。
新增提醒的起始日期、结束呼救对应的事件、待发送报告的周次在复述时固定。
缺少参数时先追问，不写入。停用提醒会保留历史记录，不等同于停药；是否继续服药请遵医嘱。
老人明确报告已经吃过药且能唯一定位药物/时间点时才记录一次；询问“吃了吗”、表示“准备吃”、确认设置提醒均不记为已服。涉及多种药或多个时间点则追问。
当前文字系统只依据老人的明确自述记录“已服”，不能客观验证药物已入口；因此健康周报应将其视为自述记录。
明确“救命”“救命，我摔倒了”直接本地记录，不等待云端或二次确认；其他表达仍由模型识别。
程序不拨打电话，也不发送通知。

## 观察结果

默认只显示面向用户的反馈，周报正文另行打印正常换行。
需要查看工具名称、模型参数、SkillResult 时加调试参数：

    python qwen_chat.py --debug
模型选工具，Python 执行技能并回传匹配 tool_call_id 的结果。
若兼容接口把修改时间的数组编码成字符串（如 "[\"09:00\"]"），程序会先解码再按时间格式校验；仍需老人确认后才修改。
工具执行后的反馈以 skill 的 speech/followup_question 为准，不采用模型的成功承诺。
每轮最多六次模型请求，同一轮相同工具和参数去重；接口失败不自动重放已完成的操作。

## 数据和身份

默认 person_id=elder_test_01，称呼为测试老人；日期取运行时北京时间。
默认数据目录是项目 data/qwen_demo，避免污染原 data 的业务记录。
三个模块共用该目录的事件流。程序固定会话身份，拒绝其他人的 ID 或记录 ID。

    python qwen_chat.py --person-id elder_test_02 --name 测试老人乙
    python qwen_chat.py --data-dir data

第二条会使用现有业务目录，初次联调建议保留默认测试目录。
终端操作者可设置 person-id，因此这是开发用身份隔离，不是生产登录认证系统。
工具返回的健康记录会发给云端模型；请使用虚构数据。

如果调度同一批测试记录，指定一致目录：

    python weekly_scheduler.py --data-dir data/qwen_demo

当前 JSON 档案尚无跨进程写锁，先串行验证：退出聊天后再运行调度检查。
不要同时运行多个聊天/调度进程写同一个数据目录。

## 退出与排错

- /exit、exit、quit 或 Ctrl+C：退出，记录保留。
- /clear：清对话历史及待确认草稿，不删除已保存记录。
- 缺少 openai：执行 python -m pip install openai。
- 401：核对密钥、地域和业务空间地址是否匹配。
- 请求失败：显示异常类别与 HTTP 状态，不打印可能含密钥的原始异常。
- 已写入操作不会因后续模型失败自动撤销，先查记录再决定是否重试。

## 离线回归

    python -m pytest tests/test_qwen_chat.py -v

通过模拟云端消息验证实际 skill 写入、完整工具回传、多轮追问、确认、越权、
非法参数、模型伪造确认、重复调用、网络错误和循环上限；不消耗 API 额度。
真实云端连通性和模型选工具效果需要在本机设置密钥后运行交互入口验证。

## 自然确认验收示例

退出旧程序后重新启动。建议指定全新测试目录，避免旧提醒影响结果：

    python qwen_chat.py --data-dir data/qwen_natural_demo

按顺序输入，观察实际反馈：

1. “每天早上八点提醒我吃一片测试药。”——复述并询问，此时尚未写入提醒。
2. “不对，改成九点。”——重新复述九点，仍不写入。
3. “对。”——只保存九点的提醒。
4. “对。”——提示没有待确认操作，不重复保存。
5. “每天十点提醒我吃一片另一种测试药。”——出现新的确认问题。
6. “算了。”——不保存第二种药的提醒。
7. 再提出第二种药的提醒，等待确认时输入“救命，我摔倒了。”——立即记录呼救，并清除提醒草稿。
8. “对。”——不能再保存被打断的提醒。
9. “帮我生成这周的健康报告。”——查看上游呼救记录进入周报及档案。
10. “取消测试药的提醒。”——先复述并询问；说“好的”后提醒停用，历史记录保留。
11. “把测试药提醒改成九点。”——先复述并询问；说“好的”后新时间生效。
12. “测试药吃了吗？”——只查询，不写已服；“我已经吃过测试药了。”才可写入一次。

每个实例的待确认状态仅保存在内存；程序重启后不会执行以前的草稿。
这是文字交互层验证，尚未接入语音识别、真实拨号或通知发送。
