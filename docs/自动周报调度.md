# 自动周报与归档

在项目根目录启动：

    python weekly_scheduler.py

进程每分钟检查一次；每周一北京时间 08:00 起生成上一周周报并归档，
无需老人查询。终端关闭或 Ctrl+C 会停止；本入口不是开机服务。
只运行一个实例。也可由系统任务计划定期调用单次命令：

    python weekly_scheduler.py --once

单次模式补跑所有已到期、有记录的历史周，没有任务时打印 []。
默认读取脚本旁的 data；自定义目录用 --data-dir，上游须写入同一事件文件。
本次未安装系统计划任务，也未启动常驻进程。

## 老人名单与文件

从共享事件 person_id 自动发现老人及有记录的周。仅呼救也建档；
无数据周不建空档案，本周未结束不归档。事件没有姓名，报告使用 person_id。
调度时钟使用北京时间，事件日期沿用共享事件接口现有日期口径。

- data/health_archives.json：个人周快照，查询模块自动刷新读取。
- data/weekly_reports/*.json：正文和统计，文件名为老人 ID 与周的哈希。
- data/weekly_scheduler.json：任务状态、指纹、时间及失败原因。

启动补跑遗漏历史周，成功且数据未变则跳过。失败下一分钟重试，其他老人继续处理。
补服或呼救状态更新触发历史周报重新生成，并刷新受影响的周际对比。
同周报告和快照覆盖更新。只调用 generate_weekly，不发送任何通知。

当前是单实例串行文件写入方案，手动生成报告应避免与调度同时写档案。
并发写需要数据库或锁；每分钟全量扫描适合当前小规模使用。
