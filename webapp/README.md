# 老人语音助手 · 可视化演示

一个网页界面，把「老人说一句话 → 大模型判断意图 → 调用 skill → 校验参数 → 执行 → 回话」
整条链路演示给观众看，并且把 **Agent 内部每一步的判断依据**都摊开在右侧。

> 组长的要求：展示成果用，做成网页就行；语音模型还在做实验，可以先接别的语音模型
> 或者模拟语音输入，只要能体现 agent 这部分功能。

## 队友怎么看这个网页

### 方式一：各自本地跑（推荐，最省事）

```bash
git pull
pip install -r requirements.txt -r webapp/requirements.txt
python webapp/app.py
```

浏览器打开终端里提示的地址（默认 **http://127.0.0.1:8000**，端口被占用会自动往后找）。

### 方式二：临时公网链接（不想装环境时）

在 `webapp/app.py` 的最后一行加上 `share=True`，启动后会打印一个
`https://xxxx.gradio.live` 的临时链接，队友直接点开就能看，**不用装任何东西**。

```python
_launch(build_app())          # 改成：build_app().launch(share=True)
```

⚠️ 注意：链接**有时效（约 72 小时）**、**需要你本机一直开着**、
且要能连上外网。适合临时演示，不适合长期。

### 方式三：等以后部署到服务器

服务器上已经有一份 skill 库，理论上也能跑这个界面；但服务器没有外网，
gradio 及其依赖需要离线传 wheel，而且只有**校园网内**能访问。
等真的要在服务器上演示了再折腾。

## 快速开始

```bash
# 1. 装依赖（skill 库 + 界面）
pip install -r requirements.txt -r webapp/requirements.txt

# 2. 启动（在仓库根目录）
python webapp/app.py
```

浏览器会自动打开 http://127.0.0.1:8000（端口被占用会自动往后找）。

> **⚠️ 关于端口**：Windows 上装了安卓模拟器 / 启用 Hyper-V / WSL 后，系统会**保留**
> 若干 TCP 端口段，绑到保留段会直接失败（表现为「所有端口都被占用」）。
> 用 `netsh interface ipv4 show excludedportrange protocol=tcp` 可以查看。
> 例如本机保留了 `7845-7944`，正好覆盖 Gradio 默认的 7860，
> 所以 `app.py` 改成从 **8000** 起自动找可用端口。

不想开网页、只想快速确认逻辑对不对：

```bash
python webapp/selftest.py     # 把演示剧本跑一遍，打印每一步
```

## 演示剧本（建议按这个顺序点）

1. 💊 **设置吃药提醒** — 完整成功路径，展示「一句话 → tool_call → 校验通过 → 执行」
2. 💊 **只说药名** — 参数不全，展示「校验不通过 → 转成追问」，**不报错、不编造**
3. 💊 **方案描述** — 「我饭后要吃两粒二甲双胍，一天三次」也算新增（但次数和时间对不上 → 追问）
4. ❓ **查用药安排** — 只读查询
5. ✅ **主动报吃药** — 老人主动上报，写一条服药记录进共享事件流
6. ✏️ **改提醒时间** — 修改已有提醒
7. ❌ **取消提醒** — 高风险操作（停药可能是医嘱也可能是记错，所以设计上要求确认）
8. 🚨 **紧急呼救** — 高风险 skill，**不做二次确认**，直接记录并产出待发送通知
9. 🚑 **问救助进度** / 🕊️ **报平安** — 状态机推进
10. 📊 **问本周表现** / 📄 **生成周报** / 📤 **发送周报** — 健康反馈**读**前面产生的数据
11. 📈 **查长期趋势** — 查个性化档案
12. 💬 **闲聊** — 不调工具，直接回应

第 10 步是重点：前面几步产生的服药记录和呼救事件，会在这一页被健康反馈真实读到，
证明三个 skill 是**有数据依赖的整体**，不是三个孤立模块。

## 哪些是真的、哪些是模拟的

| 部分 | 状态 |
|---|---|
| 三个 skill（用药提醒 / 呼救 / 健康反馈） | ✅ **真实代码**，就是仓库里的 skills/ |
| 注册表自动发现、Qwen tool schema 导出 | ✅ 真实 |
| Pydantic 参数校验、追问话术、事件流读写 | ✅ 真实 |
| 意图识别 / 填参（即大模型那一步） | ⚠️ **模拟**（`sim_qwen.py` 规则版） |
| 语音输入（ASR） | ⚠️ 用文本框模拟（组长说可以先模拟） |
| 语音播报（TTS） | ⚠️ 用文字展示「会念这句」 |
| 通知发送（短信/电话/微信） | ⚠️ 只产出 `Notification` 对象，没有真实出站 |

界面上对「模拟」的部分都做了标注（标题旁的黄色徽章、链路里的「模拟 Qwen」字样），
不会让观众误以为已经接了真模型。

## 接真 Qwen 时改哪里

只改一处：`webapp/sim_qwen.py` 的 `parse()`。

它的输出结构（`tool_name` + `arguments`）刻意和真 Qwen 的 `tool_call` 对齐，
所以把函数体换成调用 Qwen 的 OpenAI 兼容接口即可，下游
（查注册表 → Pydantic 校验 → 执行 → 回话）**一行都不用改**。

```python
resp = client.chat.completions.create(
    model="Qwen2.5-7B-Instruct",
    messages=[{"role": "system", "content": SYSTEM_PROMPT},
              {"role": "user", "content": text}],
    tools=skills.export_qwen_tools(),   # 界面第三页那张表
)
```
